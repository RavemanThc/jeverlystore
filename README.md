# Jeverly Butique

Україномовний магазин прикрас: Next.js App Router + TypeScript + Firebase Authentication. Кожен React-компонент має власний CSS Module. Глобальні стилі містять лише скидання та спільні змінні.

## Запуск

```sh
npm install
npm run dev
```

Відкрийте http://localhost:3000. Перевірка production-збірки: `npm run build`.

## Авторизація

Конфігурацію вашого Firebase Web App підключено через `.env.local`, який не потрапляє до Git. Шаблон для інших середовищ: `.env.example`.

У Firebase Console → Authentication → Sign-in method увімкніть Email/Password та Google. У Settings → Authorized domains додайте домен сайту та localhost для розробки. Після зміни змінних середовища перезапустіть dev-сервер; production потребує нової збірки.

Реалізовано вхід, реєстрацію, Google, відновлення пароля та вихід. Мова Firebase — українська. Початковий `src/firebaseconfig.js` збережено; застосунок використовує `lib/firebase.ts`, який безпечно ініціалізує Firebase один раз. Analytics автоматично не підключається.

Сервер товарів для Firebase Authentication не потрібен. Реальний вхід потребує ввімкнених провайдерів та перевірки користувачем зі своїм обліковим записом.

## Майбутній Node.js + PostgreSQL API

Поки `NEXT_PUBLIC_API_URL` порожній, каталог показує 15 товарів із 12 останніх публікацій @jeverllyb, перенесених 12 листопада 2026 року. Дані зберігаються в `data/instagram-products.json`, тексти джерел — у `data/instagram-sources.json`, фото — у `public/products`. Це локальний каталог, без автоматичної синхронізації Instagram. До PostgreSQL звертається лише ваш backend.

Коли сервер буде готовий, задайте адресу, наприклад `http://localhost:4000/api`. Очікуваний запит: GET `{NEXT_PUBLIC_API_URL}/products`.

Запропонований контракт, який можна адаптувати в `lib/products.ts`:

```json
{
  "products": [
    {
      "id": "ring-001",
      "name": "Назва прикраси",
      "category": "Каблучки",
      "material": "Підтверджений опис матеріалу",
      "description": "Опис товару",
      "price": 180,
      "currency": "USD",
      "image": "https://your-cdn.example/ring.jpg"
    }
  ]
}
```

Категорії: Каблучки, Сережки, Кольє, Браслети, Шарми. `price` — сума в основних одиницях валюти. Якщо адресу API задано, помилка сервера показується користувачу; реальний каталог не підміняється демотоварами.

`lib/api.ts` надає `authenticatedFetch` для майбутніх захищених запитів. Firebase ID token передається в Authorization: Bearer. Backend має перевіряти його через Firebase Admin `verifyIdToken` і визначати користувача за перевіреним uid. Секретні service-account ключі зберігайте лише на backend. Дозвольте CORS для адреси фронтенду та заголовка Authorization.

## Можливості та поточні обмеження

Адаптивна головна, фільтри, пошук, перегляд товару, обране та кошик із кількістю й збереженням на цьому пристрої. Діалоги підтримують Escape та утримання фокуса. Підсумки розраховуються окремо для кожної валюти.

Картки товарів використовують фотографії профілю Jeverlly. Для публікацій із кількома виробами використано спільну фотографію, а опис уточнює, за який виріб зазначена ціна. Ціни в гривнях перенесено з публікацій; залишки та розміри не підтверджені. Декоративні фотографії головного банера та секції філософії поки залишаються ілюстративними Unsplash. Профіль: https://www.instagram.com/jeverllyb/ .

Оплату, створення замовлення, розміри та залишки ще не підключено — потрібен контракт backend. Посилання Instagram відкриває профіль і нічого не надсилає автоматично. Під час оформлення сервер повинен перевіряти актуальні ціни, валюту, варіанти й залишки.

## Фірмове оформлення

Назву Jeverly Butique та оригінальний логотип JB перенесено з профілю @jeverllyb. Логотип: `public/brand/jeverly-butique.jpg` (доступна в Instagram версія 150×150). Палітра адаптована з логотипа та оформлення профілю: білий, графітовий, золотистий і пудрово-рожевий. Це візуальна адаптація, а не офіційні коди брендбука. Спільний компонент `BrandLogo` має власний CSS Module.
